# V0.3.9 player-level report refinement — uncommitted

## Scope and presentation

The accepted five-section Coach Report structure remains. Page 4 now has two columns: **Player | Recorded contributions**, grouped by team. It prints only statistics that explain why that player qualifies:

- A shooter with zero scores and three attempts shows **Shots 0/3**; no meaningless Score 0-0 or Shots 0/0 category is added.
- A KO-only contributor shows **KO wins 3** (and Marks only if recorded).
- TO won and TO lost are displayed separately only when nonzero. Their derivation is unchanged. Interceptions and defensive blocks are separate.
- Blocked shooting attempts remain explicit, distinct from defensive blocks.
- Passes, passes received and legacy possession events are named when supported by records. Generic “other attributed event(s)” is neither displayed nor used for qualification.
- Goalkeeper role, time in goal, squad membership, starting/sub/panel status and appearances alone do not qualify a Page 4 row. A keeper with a shot or another displayed contribution still qualifies. Page 3 keeper analysis is unchanged.

Full Match Data now separates **Player shooting analysis** (attempts >=1, both teams) from **Player event data** (at least one positive recorded event statistic). This removes zero-only roster rows without hiding failed attempts or non-shooting contributions. Empty event-stat columns are omitted; all populated event statistics remain, including explicit Pass roles. The original non-report interactive analysis matrix, roster controls and longitudinal Player Review are unchanged; the filtering policy is applied to the requested Coach/Full Match Data report outputs.

No squad member or event is deleted. A report-only reader names explicit legacy number-only Pass sender/receiver counts where the existing legacy statistics API lacks those fields. It does not alter the shared statistics API, create squad records, infer a receiver, generate/link permanent identities, or change turnover calculations.
