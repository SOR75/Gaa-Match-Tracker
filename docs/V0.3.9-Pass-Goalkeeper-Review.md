# V0.3.9 — simple Pass and goalkeeper Match Analysis

Uncommitted review on `sideline-v0.3.9`, based on physical-test recovery commit `fb0e254895e930608fc1e64b52a3c5bb19ca77f1`. Frozen V0.3.8 is untouched.

## Root-cause trace

### Pass

The recovery candidate had two capture routes: Pass saved an incomplete default Kick Pass and then opened the full editor, while Add build-up pass opened another route tied to the latest shot. The shared Pass fields exposed Build-up to shot / Standalone pass. That was an implementation/product-workflow mismatch, not an identity-system fault.

There is now one optional Pass action. Choose passer, receiver and Kick/Hand type, then Record pass. Opening or cancelling records nothing. One Record action creates one event using the original capture time and existing participant binding. No extra Save/Skip/confirmation stages. Live choices use Active XV; historical editing uses the complete relevant match roster. No assist/possession metric is inferred.

The duplicate button/handler, shot-association controls and linked-build-up timeline label are removed. Legacy buildUpLink/directScoreLink fields remain intact when valid, including through native History Resume and editing; they are not migrated away or reinterpreted. Timeline displays the usual passer → receiver and type.

### Goalkeeper data → statistics → presentation

Confirmed source defects:

1. goalkeeperStatistics counted kickouts only inside `if (ko && e.team === "our")`, so the opposing goalkeeper's own kickouts were always missing. Both teams are now supported, translating the existing OUR-perspective outcome into the kicking goalkeeper's retained/lost result.
2. goalkeeperPeriods existed but its time output was never connected to goalkeeperStatistics or the UI. Statistics now return periods and aggregated gkTimeMs keyed by team/matchPlayerId, retaining playerId for future reuse.
3. Both second-half transitions replaced the clock with only half/elapsedMs/startedAt, losing the measured H1 duration. A small advanceHalfClock helper preserves that duration in optional clock.completedHalves while retaining the exact reset-to-00:00/paused behaviour. It uses the existing elapsedMs calculation, not a new clock engine or nominal half length.
4. The UI was a wide table in detailed Match Analysis only. It had no time field and did not appear in the Full-Time overview. Compact cards now appear in detailed analysis/report and below the existing Full-Time dashboard, without changing that dashboard's layout/calculations.
5. Conservative legacy substitution handling differed between period replay and counter replay when an outgoing participant reference was absent. Both now clear the uncertain keeper rather than manufacturing an incoming identity.

The physical match payload was not attached. Therefore it is not possible to prove whether that particular saved match also lacked goalkeeperTrackingVersion/initial snapshots. That existing safety gate is intentionally preserved: an unsupported old/unidentified match does not gain a guessed goalkeeper just to populate cards. The UI now explains this case.

## Identity, periods and metrics

- New identified starter #1 establishes the initial keeper automatically; #16 on the bench does not.
- Existing immutable initial references plus ordered substitution events determine subsequent keepers. Incoming player directly replacing the current keeper inherits the role; reserve, outfield replacement and re-entry use the same participant IDs.
- Ordering is half, match time, then recording order for ties. No Active XV/substitution implementation is changed.
- Periods begin at match start and end at replacement/current recorded clock. Re-entry periods aggregate for the same participant.
- Measured completed-half durations support accurate cross-half time, including recorded added time. Old matches missing the boundary keep time unknown. No manual minutes or nominal 30-minute assumption is introduced.
- Goals (not points) credit the opposite active keeper's conceded count. Short misses retain the existing derived Save rule. No additional events.
- Each team's own kickouts go to its active keeper. Short/Long, retained/lost, Marks and Out of Play remain attributes of that single event. Retention uses retained / all attributed attempts, as in the previous goalkeeper model.
- Cards show name/historical jersey, recorded time, taken, retained, lost, Short/Long retention, Marks, Out of Play, Saves and Goals conceded. These are neutral recorded context, not ratings.
- No Player Review or season-dashboard UI is changed. The deterministic model accepts an explicit evaluation `now` for running-clock tests and retains permanent IDs for future aggregation.

## Compatibility and remaining risks

Match schema remains 2; History repository/storage architecture and existing records are not migrated or rewritten. The only additive persisted timing field is clock.completedHalves, recorded when the operator uses the existing half-transition controls. Resume/reload retain it through whole-match snapshots.

Time reflects the recorded match clock. If the operator never starts the clock, recorded time can be zero; if an old H1 end was never retained, total time remains unavailable. No unsupported historical goalkeeper identity or minutes are invented. Physical Safari acceptance is still required; automation is Chromium, including landscape iPad viewport tests.

Substitution, Active XV, shot selectors, kickout/Mark capture, identity binding, scoring, imports, pitch, Voice, Player Review and History/storage source implementations are unchanged from the accepted recovery commit. main.js changes are limited to Pass capture/timeline and retaining measured half-end timing.
