## Investigation before editing

- `src/substitution.js`, `src/player-credit.js` and `src/shot-capture.js` were identical to V0.3.8. The substitution/on-field functions in `src/participation.js` were also identical; V0.3.9 had only extended action evidence for Player Review.
- V0.3.8 itself contains both roster buttons and manual jersey fallback fields in the substitution modal. Raw-field-only rendering occurs when the selected team's numbered roster is empty. This may mean a different active team, an empty squad, or a loaded name-only squad whose match jerseys have not been assigned. The precise physical-iPad state was not supplied and cannot be proven from source comparison alone. No claim is made that an underlying substitution-engine regression was found.
- The established shot picker uses Active XV and only generates fallback 1–15 when the team's squad is empty. A populated #1–15 + substitutes match does not reproduce the reported stale selector in the reviewed code. New regression tests exercise the complete actual UI after #18 ON / #10 OFF, reload, editing, undo and native History Resume.
- The NEW Pass editor did bypass Active XV: it opened as an editor using includeInactive=true. This is corrected for immediate live Pass credit; historical editing and retrospective build-up intentionally retain access to the complete match roster.
- The goalkeeper failure was caused by the candidate requiring manual configuration. Without it, the model had no goalkeeper reference. That configuration UI is removed.
- The generic Excel path read the first worksheet without checking workbook type. Thus an official Squad Setup sheet could be parsed as player candidates. The dedicated official importer was already separate and correct. Both upload entry points now recognise official workbooks and use the dedicated official review/creation flow.
- OCR parsers, recognition, thresholds and photo routes were unchanged from V0.3.8. No new physical photo or raw OCR output accompanies this request, so the reported repeated #2 cannot be traced to a specific photograph here. Existing real-photo tests are retained, not replaced by new synthetic images. No OCR matching/recognition rules are changed.

## Recovery behaviour

### Substitutions and live selectors

Reuse the original roster-button substitution UI and Active XV engine. The only substitution source change adds an explicit team-named warning when no numbered participants exist, rather than an unexplained raw-input-only view. No jerseys or participants are fabricated.

After #18 ON / #10 OFF, shots, our kickout winners, Marks, turnovers, interceptions, defensive blocks, possession credit and immediate Pass selectors include #18 and exclude #10. Editing old events and retrospective passes can still credit players who were on the field earlier. No second on-field engine is introduced.

### Goalkeepers

New matches have an additive `goalkeeperTrackingVersion: 1` opt-in. A unique identified starter #1 is the initial goalkeeper; #16 existing on the bench does not establish any role. The first live event freezes initial participant references in the match snapshot. Subsequently, the existing substitution events transfer goalkeeper identity to the player replacing the current keeper, including reserve, outfield replacement and re-entry.

Older matches without this opt-in are not assigned a goalkeeper by jersey/name inference. Previously explicit V0.3.9 goalkeeper snapshots/change events remain readable; there is no new manual selector. If play begins without an identified starting #1, goalkeeper attribution remains unknown rather than being retroactively manufactured.

Kickouts, Short saves and goals conceded continue deriving from the existing event log. `goalkeeperPeriods()` exposes objective identity/time boundaries. Cross-half duration is null when the exact H1 end time is unavailable; no nominal-duration minutes are invented. No subjective ratings are added.

### Kickouts

Every won/lost outcome immediately saves ONE kickout and shows the winning side's number grid inside that same modal. A player tap updates the same ID, stores a `kickoutWinner` participant reference, and closes. An empty squad uses existing anonymous 1–15/Other number behaviour, without creating player records. Our roster follows Active XV; opposition keeps the established roster/fallback behaviour.

There is no Skip Player or extra Save button, and kickouts no longer use the collapsed live Credit player panel. The close X/Escape can dismiss an already-recorded event if the operator cannot attribute it. Out of Play saves and closes immediately, with no player picker.

Mark remains an attribute. Our Mark credit retains the legacy markPlayerNumber/reference for compatibility. Player analysis shows possessions won, Marks and other wins separately. Seven wins containing four Marks produce 7 / 4 / 3, never eleven events. Editing to a different winning team clears the prior winner until a player on the new side is explicitly selected. Mark-only corrections can retain the same winner. Undo, edits and aggregation remain event-derived.

The wide Kickout Analysis table is deliberately left as a V0.3.9 responsive-UI follow-up. It is not redesigned in this recovery.

### Excel

`Official-routing.xlsx` is a representative official-structure workbook, explicitly fictional test players: Squad Setup first, Instructions, then Players. Metadata includes the reported club/squad/season/code/coach/instruction examples. Only the Players table below Player Name is parsed; known Sideline instruction rows are excluded even if placed below it. Default No. is ignored, Unicode is preserved and duplicate names stay separate. Permanent IDs are created only on CREATE SQUAD. The real coach workbook was not attached to this request.

### Retained V0.3.9 behaviour

Out of Play, optional Hand/Kick Passes, retrospective shot links, two-sided turnover references, goalkeeper saves/conceded/kickout analysis and permanent-ID Player Review remain. Possession remains a single optional recorded event/count; no possession percentage or duration is inferred.
