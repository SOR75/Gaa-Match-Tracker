## Architecture

- `src/analysis-stream.js`: pure chronological projection of the existing event
  ledger. Uses the accepted Period, Identity, Kickout, Shot, Goalkeeper and Field
  State readers. No second event database, schema migration or historical writes.
- `src/match-flow.js`: conservative possession evidence, opportunities, candidate
  spells, deterministic ranking and story merging. This is separate from capture.
- `src/score-windows.js`: shared score-window detector used by production analysis
  and the sparse factual benchmark. Minor responses can remain inside a broader
  swing; uninterrupted runs use a strict reversal boundary.
- `src/match-flow-ui.js` / `.css`: restrained additive Match Flow section beneath
  the accepted HT/FT dashboard, with expandable event evidence. No report redesign.

## Canonical event stream / CSV

Each projected row retains original event ID, chronological and recording order,
period/local milliseconds and continuous milliseconds (only when measured earlier
period durations are known), team, outcome, role-specific player references,
recorded permanent IDs, jersey snapshots, shot/source/reason/coordinates,
kickout length/winner/Mark, notable Pass from/to/type, paired turnover sides,
interception/block, derived keeper, substitution, card, valid field counts and
before/after scores. Missing values stay null. Legacy number-only players remain
unlinked. Unknown/scouting lineups are not automatically labelled 15v15.

CSV exports all canonical football rows, independent of visible Timeline filters.
It includes both human clocks and millisecond clocks, attribution/evidence fields,
invalid-fact warnings, notes/dictation and coach observations. UTF-8 BOM and CRLF
support spreadsheets; quoted fields preserve commas/newlines/Unicode and user
text is protected against spreadsheet formula execution. Negative numeric score
margins remain numbers. No data is written back. Current Timeline and HT/FT views
export the current match; read-only History exports the selected saved match.
The separate untimed penalty-shootout ledger is not relabelled as timed football
or included in possession/scoring-flow analysis.

## Possession evidence

- Sources: explicit kickout win, turnover outcome, interception or explicit
  retained/lost possession fact. A Mark is an attribute of one kickout possession;
  its opportunity row is a labelled subset, never a second possession.
- Out of Play is not an invented possession winner. Existing kickout statistics
  continue to count it as a loss for the kicker, unchanged.
- A score or Wide ends the attack; an explicit new source replaces the previous
  source. Opposing attacking evidence, unknown possession, invalid facts and
  period end prevent an unsupported continuation.
- Saves, Blocks, Short and Post do not automatically transfer possession.
- Passes can enrich a recorded sequence but never create or establish one. Zero
  Pass matches work. No event gap is filled with imagined passing or possession.
- An explicit stored build-up/score link supports CONFIRMED opportunity credit.
  Otherwise same-team source/shot adjacency is only PROBABLE, even when no
  contradiction is recorded. Both counts remain separate in opportunity outputs.
- A score → opposition restart won → score may be a DIRECT_EVENT_CHAIN of
  recorded actions, including optional same-team notable Passes. This describes
  the recorded sequence, not proof of unrecorded continuous play or causation.

## Meaning and ranking

Candidate families cover unanswered scoring runs, broader margin swings, late
lead changes, contextual repeated restarts, possession-win/shot/score sequences,
numerical spells, post-substitution windows and adequately sampled shooting
changes. Strong recoveries use the same evidence rules as negative spells.

Ranking has inspectable components: score impact, pattern strength, supporting
recorded event types, direct recorded consequence and close/late/ET context.
No random/opaque AI score is used. A repeated kickout count alone is not enough
for a story. Shooting comparison requires at least five attempts in each sample.
A late go-ahead point can qualify without forcing a multi-score-run minimum.
Overlapping same-team evidence merges into a stronger story; opposite-team
recovery remains distinct. Every observation retains original event IDs and its
supporting candidates. Merged windows retain the union of their evidence spans.

FT displays at most five strong stories; HT at most three, and either may show
zero. CONTEXT candidates do not become standalone cards merely to fill space.
No conventional possession percentage, assists, pass-completion percentage,
complete passing volume, tactical intent, missing length, missing identity or
missing location is inferred.

The user confirmed no event export is available. The supplied facts are stored
in `tests/fixtures/match-flow/manchans-vincents-partial.json`. Original event IDs,
match ID, measured period durations and unavailable event attributes are null.
The factual turnover/kickout entries remain separate, with unknown player and
kickout length. No possession continuity is created between them and the scores.

The shared score-window detector actually generates, in ranked order:

1. **Vincents — 10-point margin swing** (rank 20 in the sparse diagnostic).
   H1 22:16: Manchans 6–1 → level at HT → H2 08:37: Manchans 7–12.
   Vincents scored 11 scoreboard points while conceding 1 between the supplied
   checkpoints. Evidence references are the two supplied timed score
   checkpoints; the separate HT state is level with unknown exact team totals; original event IDs are unavailable, so the event-ID array is empty.
2. **Manchans — 6 unanswered points** (rank 15 in the sparse diagnostic).
   H2 08:37: 7–12 → six supplied points at 10:40, 11:50, 13:00, 13:51,
   14:36, 15:51 → 13–12. The six score times span **5:11**. Evidence references
   are the supplied baseline and each of those six times, not invented event IDs.

12–7 is **five** behind; six points changes that to one ahead. The narrative's
“four behind” phrase is not used. The HT score totals and elapsed duration are unknown, so no
continuous cross-half duration is invented. The exact six point timestamps are
retained; the baseline-to-last-score window is not mislabelled as 5:11.

**Not verified:** four individual Long kickouts, exact restart IDs/times, later
Mark/restart-to-goal sequence, full-match ranking and omitted recorded events.
These cannot be claimed from the partial data. The general synthetic regression
separately tests four explicit Long kickouts, cross-half merging and the 36-second
restart sequence, clearly labelled synthetic and with different team labels.

A future unchanged real match object can populate `fullMatch` in the benchmark;
