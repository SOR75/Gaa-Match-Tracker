# Official Sideline Squad Excel import — local checkpoint

## Current official template

The Players sheet presented to coaches has one column:

- **Player Name \*** — required.
The permanent Squad establishes WHO is a member. Today’s jersey and playing position belong to the match.

Names are trimmed and whitespace/accidental line breaks collapsed to spaces. Unicode accents, apostrophes and coach-entered capitalisation are preserved. Unused rows are ignored. Duplicate names are warnings and remain separate people with distinct permanent IDs.

Older Default No., Preferred Position, Second Position and Status columns remain tolerated but are ignored, including invalid/duplicate values. They cannot block import or force match jerseys. Imported players are current/active Squad members with blank jerseys/positions and panel roles until today’s team is chosen. Existing permanent IDs, match positions, roster roles and historical snapshots remain unchanged.

Saved Squad loads in the live UI use match-day mode: newly loaded people start blank/unselected; players already linked in this same match retain their current jerseys/roles/local IDs. The batch Today’s team editor saves numbers and Starter/Substitute/Panel roles atomically, allowing number swaps without intermediate collisions. Permanent Saved Squad data is not rewritten.

Availability history (Available/Injured/Unavailable/Suspended with dates) is future work. It must reference permanent playerId independently of match selection and is not derived from old Excel Status values.

## Metadata and supported workbook

`Squad Setup` retains Club Name, Squad Name, Season, Code and optional Coach / Manager key/value rows; their values may be blank. Titles above the fields are allowed. `Players` uses the official name column, not arbitrary spreadsheet layouts. Asterisk/trailing header full stop are normalised; unexpected player columns are rejected with template guidance. Both named sheets must exist. Only `.xlsx` under 15 MB is accepted.

Club/squad/season/code/coach text is preserved alongside permanent Squad ID and nullable clubId/seasonId. A human-entered Season does not generate a fake seasonId. There is no Club/Season management UI.

No original completed real county workbook was attached to this instruction or found among the supplied workspace files. Tests use deterministic fictional workbooks matching the specified official contract. The real completed workbook remains a physical iPad test input, not a claimed automated fixture.

## Workflow and identity

Squad → IMPORT SIDELINE SQUAD → choose workbook → SQUAD IMPORT REVIEW → correct names/metadata → CREATE SQUAD → Saved squads → Load.

Review shows found/ready/review counts, player-name fields, row warnings and add/delete controls. No imported UUIDs are created during parsing/review. Cancel changes neither the active match nor library. CREATE SQUAD uses the approved identity factory to create a separate UUID for each person. Creation does not automatically replace the current match roster.

Ignored legacy default 23 → match #6 → #8 → #11 retains the same permanent playerId and independent matchPlayerIds/snapshots. Saved name/default-number edits preserve IDs. History stores full match payloads, preserving IDs, attribution, jerseys, scores and coordinates. Legacy events remain unlinked. No new repository/store/schema migration is needed for this refinement.

## Offline and privacy

The existing bundled read-excel-file reader parses locally. No upload/API/cloud or new dependency is added. Production asset precaching supports offline import after the app has loaded; no PWA architecture changes are made. No DOB, contact, parent or medical fields are imported.

## Regression fixtures

- County-30.xlsx and County-29.xlsx: name-only county-sized squads with unused slots.
- Club-21.xlsx: 21 names, no number column.
- Name-only.xlsx: Player Name column alone.
- Unicode-names.xlsx: accented names, whitespace/newlines, capitalisation and duplicate-name separation.
- Legacy-rich.xlsx: ignored position/status fields including unsupported/long values and unused rows.
- Review-errors.xlsx: duplicate names plus ignored legacy default values and unused rows.
- Missing-Players.xlsx, Wrong-columns.xlsx, Malformed.xlsx: unsupported input handling.

Unit/browser tests cover creation, reload/Load, identity across jersey changes, native History, correction/cancel and offline import. Existing real-photo OCR fixtures remain unchanged.

Physical iPad Safari acceptance still needs the real workbook, Files picker, review scrolling/editing, installed-PWA offline import and reopening persistence. iCloud-only workbooks must first be downloaded locally. Chromium automation does not establish Safari acceptance.
