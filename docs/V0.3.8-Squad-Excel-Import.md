# Official Sideline Squad Excel import — local checkpoint

## Current official template

The Players sheet presented to coaches has only:

- **Player Name \*** — required.
- **Default No.** — optional, blank or integer 1–99; never identity.

A name-only worksheet is also accepted without the optional Default No. column. Names are trimmed and whitespace/accidental line breaks collapsed to spaces. Unicode accents, apostrophes and coach-entered capitalisation are preserved. Unused rows are ignored; a number without a name is retained for review. Duplicate names are warnings and remain separate players; duplicate default numbers must be corrected or cleared, never merged.

The older Preferred Position, Second Position and Status columns remain tolerated but are ignored, including invalid/unsupported values. They cannot block import. No Excel playing-position or availability information is saved: imported players start as current/active Squad members with blank legacy position fields. Existing match-specific position and role editing remains unchanged. The pre-existing identity model and historical Squad data are preserved; no schema/availability migration is performed.

Availability history (Available/Injured/Unavailable/Suspended with dates) is future work and is not derived from Excel Status. It can later reference permanent playerId independently of match selection or jersey number.

## Metadata and supported workbook

`Squad Setup` retains Club Name, Squad Name, Season, Code and optional Coach / Manager key/value rows; their values may be blank. Titles above the fields are allowed. `Players` uses the official columns, not arbitrary spreadsheet layouts. Asterisk/trailing header full stop are normalised; unexpected player columns are rejected with template guidance. Both named sheets must exist. Only `.xlsx` under 15 MB is accepted.

Club/squad/season/code/coach text is preserved alongside permanent Squad ID and nullable clubId/seasonId. A human-entered Season does not generate a fake seasonId. There is no Club/Season management UI.

No original completed real county workbook was attached to this instruction or found among the supplied workspace files. Tests use deterministic fictional workbooks matching the specified official contract. The real completed workbook remains a physical iPad test input, not a claimed automated fixture.

## Workflow and identity

Squad → IMPORT SIDELINE SQUAD → choose workbook → SQUAD IMPORT REVIEW → correct names/numbers/metadata → CREATE SQUAD → Saved squads → Load.

Review shows found/ready/review counts, name/default-number fields, row warnings and add/delete controls. No imported UUIDs are created during parsing/review. Cancel changes neither the active match nor library. CREATE SQUAD uses the approved identity factory to create a separate UUID for each person. Creation does not automatically replace the current match roster.

Default 23 → match #6 → #8 → #11 retains the same permanent playerId and independent matchPlayerIds/snapshots. Saved name/default-number edits preserve IDs. History stores full match payloads, preserving IDs, attribution, jerseys, scores and coordinates. Legacy events remain unlinked. No new repository/store/schema migration is needed for this refinement.

## Offline and privacy

The existing bundled read-excel-file reader parses locally. No upload/API/cloud or new dependency is added. Production asset precaching supports offline import after the app has loaded; no PWA architecture changes are made. No DOB, contact, parent or medical fields are imported.

## Regression fixtures

`tests/fixtures/squad-template/generate.py` reproducibly creates fictional workbooks:

- County-30.xlsx and County-29.xlsx: two-column county-sized squads with unused slots.
- Club-21.xlsx: 21 names, blank optional numbers.
- Name-only.xlsx: Player Name column alone.
- Unicode-names.xlsx: accented names, whitespace/newlines, capitalisation and duplicate-name separation.
- Legacy-rich.xlsx: ignored position/status fields including unsupported/long values and unused rows.
- Review-errors.xlsx: duplicate names/default numbers, invalid number, blank-name partial row.
- Missing-Players.xlsx, Wrong-columns.xlsx, Malformed.xlsx: unsupported input handling.

Unit/browser tests cover creation, reload/Load, identity across jersey changes, native History, correction/cancel and offline import. Existing real-photo OCR fixtures remain unchanged.

Physical iPad Safari acceptance still needs the real workbook, Files picker, review scrolling/editing, installed-PWA offline import and reopening persistence. iCloud-only workbooks must first be downloaded locally. Chromium automation does not establish Safari acceptance.
