# V0.3.8 final local workflow refinements

Base: physical-test candidate `f4660d828ce4fff6c3fcbe9502dfdb206a7e4f81`. Keep V0.3.8-dev. No commit, push, deployment or tag until review.

## Reusable Team Setup

Permanent Saved Squad = WHO. Saved Team Setup = reusable match defaults. Match = independently editable snapshot.

`sideline.team-setups.v1` stores `{version:1,setups:[...]}`. Each setup has its own UUID, name, source squadId, creation time, and entries containing only playerId, number (nullable) and Starter/Substitute/Panel role. It creates no permanent players and stores no shared match roster objects or old matchPlayerIds.

Squad → Save team setup → choose a new name → Save setup. An existing name is rejected rather than silently overwritten. The current roster must already reference real permanent members of its source Saved Squad; ad-hoc/unlinked players are not guessed or promoted to permanent people.

Next match → Squad → Use saved team setup → Use setup. This loads current source Squad names/IDs and a separate match copy of default jerseys/roles, preserving current matchPlayerIds only where already linked in this same match. New matches get their own local IDs. Set today’s team to alter only the players/numbers/roles that differ. The setup and previous matches are unchanged.

Replacing a populated current roster requires confirmation. Applying a setup to a completed current match is disabled: start a new match first. Saving defaults from a completed match is allowed and does not mutate it. Added source-Squad members stay blank/unselected; removed members cause a review error rather than silently guessing replacements. A missing/deleted source Squad leaves its setups unavailable, without cascading deletion. Corrupt setup storage is preserved and prevents overwriting it.

## Starter-count advisory

On Live Match, a roster with a count other than 15 receives a visible, non-modal warning before play evidence exists: “11 players selected to start. A standard team has 15 starters.” Review team opens the existing Today’s Team editor. Continue anyway acknowledges the current lineup and removes the advisory. Tracking controls are never disabled; the clock/events work with 11 or 16 starters. No exact-XV gate is introduced.

The prior maximum-15 restriction in the batch editor is removed so 16 can be saved and explicitly reviewed. The active-player/substitution engine is unchanged. Acknowledgement is additive match UI metadata keyed to current player IDs/roles; changing the lineup can show the advisory again before play. Empty-squad number fallback remains uninterrupted. During a match, existing play evidence suppresses repeated startup warnings.

The advisory is outside the page heading because compact landscape iPad deliberately hides that heading. This keeps both Review team and Continue anyway visible on iPad without changing the established compact match layout.

Existing conservative Player Review rules remain: more than 15 recorded starters can still require participation review rather than automatically crediting every member with an appearance. This refinement does not redesign that accepted participation model.

## Delete Saved Squad

Saved squads → Edit → Delete saved squad → explicit named confirmation. Cancel restores the edit form, including unsaved field values. Delete squad removes only the Squad library entry and explains that existing matches/historical records will not be deleted.

The deletion helper never accesses active-match, archive, IndexedDB History, event, shot, participation or Team Setup storage. History and identity-linked Player Review remain available from archived match payloads. Missing source-Squad display metadata does not remove player IDs, names, jerseys, events or calculated statistics.

## Kickout player observations

A deterministic individual pattern requires **at least 3 distinct qualifying successful kickout event IDs credited to one player**. One/two events never qualify. A Mark is an attribute of that kickout and cannot count it twice. Unknown outcomes, unsuccessful credits, missing/invalid jersey attribution do not qualify.

- Opposition: opposition-kickout retained by the opposition (LOST from our perspective) with an opposition main-player credit. “Dublin retained 6 of 6 … #8 was credited on 5” is factual; no receiver, catch, target zone or matchup is invented.
- Our team: our main-player credit on a kickout WON by us, or the explicit our-team Mark-winner role on either kickout type. Mere opposition-player attribution when we win their kickout is not reinterpreted as an our-team identity.
- Stable permanent/local identity references take priority; legacy unlinked number references stay separate. Display names are never aggregation keys. Multiple recorded jerseys for a linked player can be shown together.
- At most one strongest candidate per side (highest distinct-event count, then explicit Mark count, then stable key) keeps noise down.

The existing team kickout observation is enhanced in the same card when present; its team-level evidence remains. If no corresponding team card exists, a factual player card is added. The five-known-outcome threshold for the original team-rate rule is unchanged. H1/H2/full-match observations all use their existing scoped event subsets and recalculate after edits/undo. Scoring, retention calculations and statistical definitions are unchanged. There is no AI or speculative coaching prescription.
