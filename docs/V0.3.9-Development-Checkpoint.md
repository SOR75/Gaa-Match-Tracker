# V0.3.9 development checkpoint

Based on physically accepted V0.3.8 commit `6653d775c72bc0a4f5e6a21e16b695f57ccf63b5`. This is a development/iPad review build, not a release.

## Capture

- Existing five-choice kickout capture replaces Unknown with Out of Play / Sideline. Short/Long and Mark credit remain unchanged. Old Unknown records retain their meaning and remain editable without conversion to a win.
- Pass is optional, below the original main event grid so the established iPad buttons remain visible. Tapping Pass saves a standalone Kick Pass immediately, then opens optional passer/receiver/type editing. Cancel does not delete that saved pass; Undo does. Choose Hand Pass or Kick Pass.
- Add build-up pass to last shot opens an optional retrospective editor. It uses that shot's team/half/time, independently of the current live team selection. Choose players and save; adjust the half/time if known. Repeat for significant passes only. Each pass links to the existing shot ID, including unsuccessful attempts. No extra shot or score is created. Cancel before saving adds nothing. Editing a target to a non-shot or another team, or undoing a target, clears invalid links. Recording order remains the undo order.
- Turnover capture remains one tap. Edit Last/Event offers optional winner and loser from the respective teams. Existing immediate optional player credit still works. One incident credits both participants when known; unknown counterparts are not inferred. No extra turnover event is created.

## Goalkeepers

Open Goalkeepers below the event grid after loading today's lineup. Explicitly select each identifiable goalkeeper: #1 is not permanently assumed. Before any events, selection records the starting goalkeeper reference. Once events exist, changing/clearing the selector records a timestamped Goalkeeper change, editable/undoable through the same event log. Initial selection can be corrected before the first event. After play, correct recorded changes through event editing; do not retrospectively guess an unidentified initial keeper.

A substitution replacing the identified goalkeeper transfers the role to the incoming participant, including re-entry. Outfield role changes without a substitution use the same explicit goalkeeper selector. Events sort by half/time, with recording order breaking ties. Unknown/number-only legacy substitutions cannot establish a new permanent keeper identity; they clear attribution if the identified keeper leaves.

Derived from original events, without duplicate save/conceded/shot events:

- Our kickouts: taken, won/retained, lost, Short/Long attempted and retained, retention percentages, Marks generated, Out of Play / Sideline.
- Marks generated counts any recorded Mark on that goalkeeper's own kickout, whether won by us or opposition. Receiving-player Mark credit remains separate.
- Opposition Miss → Short credits our active goalkeeper a Save. Our Miss → Short credits an identified opposing goalkeeper. Saved/Wide/Post/Blocked/Other and goals do not create this derived Save.
- A scored goal credits the active opposing goalkeeper one Goal Conceded.

Goalkeeper retention uses retained / all attributed attempts, including Out of Play and unknown attempts in the denominator. The established team kickout retention continues using known won/lost outcomes only; Out of Play is explicitly separate from both. This intentional denominator difference is visible in the table's attempted counts.

Detailed Match Analysis/Match Report has a goalkeeper section; Player Review aggregates our linked goalkeeper counters by permanent playerId across different match jerseys. Percentages are recomputed from summed numerators/denominators, not averaged. Player Review shows career totals and a goalkeeper season table keyed by stored seasonId; records without an ID remain explicitly grouped as Season not recorded. No season is inferred from date, name or jersey. Legacy/unlinked data is never joined to a permanent player by name/number.

## Additive data; no migration

- Optional `match.goalkeepers.{our,opposition}` initial participant snapshots.
- New event types `pass`, `goalkeeper-change`.
- Pass fields `passType`, `receiverNumber`, `buildUpLink`.
- Turnover fields `turnoverWinnerNumber`, `turnoverLoserNumber`.
- Optional participant roles `receiver`, `turnoverWinner`, `turnoverLoser`, using the existing identityVersion 1 reference shape. Original references and numeric legacy fields remain supported.
- Kickout outcome `out-of-play`; existing Unknown is not rewritten.

Match schema remains 2 and IndexedDB repository remains unchanged. Whole-match History snapshots carry these optional fields without repository changes. Older matches remain readable in V0.3.9; older applications are not expected to understand newly introduced event types. No existing archives are rewritten by this checkpoint. Continue to preserve the frozen V0.3.8 release for fallback.
