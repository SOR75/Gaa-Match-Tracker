# V0.3.8 local physical-test refinement

Based on pushed checkpoint `ddf90b57c104f3de50c224495da5f3ac0a262105`. No push, deployment, tag, storage-schema migration or release change in this refinement.

## Player Review

The new device-local Player Review navigation reads the existing History repository and current match plus Saved Squad library. The current match replaces a same-ID archived snapshot to avoid double-counting. Records are ordered by match date, with existing timestamps/IDs as fallbacks. No materialised player-profile database or server is added.

Profiles aggregate **only permanent playerId UUIDs**, with matchPlayerId used for within-match references. The Saved Squad name/current player name is preferred where available; historic names and jerseys remain in the original match snapshots. Two same-name people remain separate; legacy/unlinked names/jerseys are not merged. The initial review is explicitly for our-team performances, not anonymous opposition numbers.

The screen provides name/Squad, matches in squad, appearances, confirmed starts, substitute appearances, no recorded participation in completed matches, last up-to-six qualifying matches with actual denominator, shooting and recorded defensive/contribution statistics. Shooting conversion is combined successes/attempts, never the average of percentages. Match rows retain each match’s jersey, participation evidence, scores, shots and contributions. View match opens the existing read-only historical analysis without replacing the active match.

A qualifying match has recorded events, clock activity or explicit completion. Setup-only rows do not manufacture appearances. Starting roles in a plausible starting XV are evidence of a start once match activity exists. A linked substitution-on or attributed event is also evidence of participation. Bench/panel membership alone is not an appearance. A completed match with no entry/action is labelled Did not play/no appearance recorded; this is event-log evidence, not an availability judgement. Missing capture cannot prove real-world absence.

Older bulk-loaded squads with more than 15 recorded starters are ambiguous: do not credit all of them with starts/appearances or assert DNP. Explicit linked events still establish appearances, with unverified role where needed. Review evidence flags the starting-lineup issue. No names/jersey-order guesses or automatic legacy linking are made. No minutes-played, injury, suspension or availability history is built.

## Active players

`participation.js` deterministically reconstructs local on-field keys from roster starting roles and substitution events in half/time/recording order. Stable matchPlayerId references take priority; existing within-match number-only substitution fallback is retained for legacy records. No independent mutable active-player store is introduced.

Ordinary our-team Shot, Defensive Block and Mark selectors use the shared active roster. Off players disappear and replacements appear; panel players can enter if selected ON. Substitution ON offers inactive numbered players, OFF offers active players; re-entry is allowed. Undo, corrected substitutions, reload and Resume reconstruct from the event log. Historical editing retains full-roster choices, including previously substituted players. Empty-squad number fallback and manual optional numbers remain supported.

Interception, turnover and possession taps still save immediately. A collapsed optional player-credit panel uses the same active selector and updates the same event ID; it never blocks the next event or adds a confirmation screen. Kickout main-player credit can also use this panel. The existing separate Mark winner flow remains intact.

## Match-day team and New Match

Saved Squad loading in the live UI leaves new match jerseys/positions blank and roles Panel. Already-linked people in the same match retain today’s assignments. A batch Today’s team table edits all jerseys/starting roles together and validates final uniqueness once, enabling atomic number swaps without editing permanent identity. At most 15 starters can be assigned in the new batch workflow. During play, use Substitution; starting-role changes are deliberate lineup corrections.

Match Setup explicitly says it edits the current match and changing opponent does not create another record. A prominent Start a new blank match action confirms the current fixture/event count and uses the existing archive-before-replace repository operation. Saved Squads are unaffected. No silent new-record creation or destructive replacement is added.

## Template

Official Players sheet: **Player Name \*** only. Older Default No./positions/status are tolerated and ignored. All imported names receive separate IDs only on CREATE SQUAD; new members are current/active, with blank jerseys and unselected roles. A full batch match-day assignment follows Load. Excel still parses locally/offline using the existing bundled reader. Fictional workbook fixtures exercise name-only and legacy compatibility; protected real OCR photographs are unchanged.
